# 長文タスクの差分readを1秒未満にする

## 目標と計測

対象タスク`01a070ad-2740-7382-8fd8-e9f6f013f92d`について、通常の差分readを新しいCLIプロセスで繰り返し実行し、全試行の実測を1秒未満にする。以前の実測は、差分0件でも10.51秒、受信約124.5MB。変更ありの差分は隔離プロトコル環境でも確認する。

## 取得方式

- 全履歴を必要とする経路も、最初はメタデータのみ読み、項目を二重取得しない。
- 通常readはメタデータと項目ページを利用する。初回は最新側から必要件数を取得する。
- v2 cursorはサーバーの項目再開位置、確認済みターンID・状態、末尾の項目ID・ハッシュ、実行中項目を再取得する位置を保持する。本文はcursorに保存しない。
- 差分は確認済み末尾を再取得してIDを照合し、その後の新着を読む。実行中項目は元のページを再取得し、途中出力・完了をupdatedとして返す。送信や購読のためにタスクを再開しない。
- 初回に実行中ターンがある場合は、そのターンを走査して、末尾より前にある実行中コマンドも追跡する。過去の完了ターンの全項目は取得しない。
- 上限で返せなかった項目・更新はcursorを進めず、次回も取得できるようにする。
- 通常差分の前方走査は1回10ページまでとし、内部項目しかない大量の新着でも`has_more`で次回へ渡す。Monitorとchange待機は、表示する変化がなくても残りページを読み進める。
- ターン開始がメタデータ取得と項目取得の間に重なった場合は、同じcursorで1回だけ再取得する。巻き戻しや不一致のエラーではcursorを取り直さない。

## 整合性と互換性

- ターン列の巻き戻し・置換、末尾や追跡対象項目の消失・不一致はSTALE_CURSORとし、黙って取り直さない。
- 通常経路が確認する範囲を`history_scope`で明示する。過去の全本文をハッシュ照合したとは扱わない。未取得の古い項目の正確な総件数はUnknownとして返す。
- `--full-history`は従来の全履歴ハッシュ照合を残す。v1 cursorはこの明示モードで読み取れる。通常経路では新しいreadでv2 cursorを取得するよう案内する。
- `--based-on`はv2の位置以降のユーザー入力、ターン変更、アンカー不一致を検出する。進捗報告だけでは送信を止めない。
- `has_more:true`のv2 cursorは送信に使えない。読み残した入力を確認してから判断する。
- Monitorと通常watchは同じ差分取得を使う。時間切れ時の余分な全取得を削除する。

## 検証条件

新着、更新中項目の完了、出力更新、ページ境界、表示上限、空ターン、タスク停止・再開、ロールバック、古いcursor、別タスクのcursor、切断と中断、送信直前の新しいユーザー入力を検証する。大きな過去履歴があっても通常差分が全履歴APIを呼ばないことをテストする。実タスクへの書き込みはせず、変更ありのケースは隔離したCodexと模擬モデルで作る。

全履歴の重複解消と、通常のページ読み取り（監視・送信鮮度との統合を含む）を機能単位でコミットする。テストとhelpを各機能に含め、[実測結果](read-performance-results.md)と再計測コマンドを残す。
